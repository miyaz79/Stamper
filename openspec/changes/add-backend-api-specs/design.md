## Context
この変更は最小限のバックエンド API 仕様を明確化することを目的とする。既存の実装やパターンを大きく変えずに、段階的に実装できるようにする。

## Decisions
- 採用: JWT ベースの認証（既存の `lib/jwt.ts` を再利用する）
- シンプルさ優先: 初期段階では DB マイグレーションや複雑なスキーマ変更は行わない。必要に応じて別 change を作る。

## Risks / Trade-offs
- 低リスクだが、将来的な拡張（ロール、権限、ペイロード拡張）は別提案で扱う。

## Open Questions
- 実際のユーザー情報のソース（ハードコード、モック、DB）はどれを使うか？（初期はモック/テスト用データで良いと仮定）
